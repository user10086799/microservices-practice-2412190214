# 项目提案

## 项目名称

分布式购物系统

## 目标用户

- 普通消费者：浏览商品、加入购物车、下单并查看订单状态。
- 商家：发布商品、管理库存、处理发货。
- 系统管理员：管理用户与商品分类，查看系统运行状态。

## 本周要实现的核心业务流程

买家浏览商品并提交订单：

1. 查询商品列表，查看某一件商品的名称、价格和库存。
2. 选择该商品并填写购买数量，创建一笔待支付订单。
3. 系统计算订单金额并扣减对应库存。
4. 查询刚创建的订单，确认状态为待支付。

支付、发货和评价留到后续周次。

## 参与流程的业务实体

- 商品：名称、描述、价格、库存数量。
- 订单：买家姓名、关联的商品、购买数量、订单金额、订单状态。

关系：一个商品可以对应多笔订单，一笔订单在本周只关联一个商品。

## 业务规则

下单数量必须大于 0，且不能超过该商品的当前库存。规则在 `OrderService` 中检查。数量不合法或超过库存时拒绝创建订单，不扣减库存；检查通过后扣减库存，金额等于商品单价乘以数量，订单状态为 `PENDING_PAYMENT`（待支付）。
